### 3. CatVTON head-cutting + body-distortion fix (08d6a87 — the important one)
**Root cause found in the node source:** CatVTON's `CatVTON` node does
`resize_and_crop(target_image, (768,1024))` — a **center-crop to 3:4**. Photos
that aren't exactly 3:4 (e.g. 576×1246 tall, or 5312×2988 stored landscape w/
EXIF rotation) had their **head sliced off**, and EXIF-rotated photos were fed
**sideways** → distorted proportions (the "fatter" look).

**Fix:** `tryon._prep_person()` (in `tryon.py`) runs before every CatVTON call:
1. `ImageOps.exif_transpose` → portrait photos are upright.
2. **Letterbox** the full body onto the 768×1024 canvas (pad gray, **never crop**)
   → CatVTON's internal crop becomes a no-op. Head & feet always preserved.

Verified live on the tall 576×1246 photo: render now keeps the face. Regression
test in `tests/test_wardrobe.py` (`test_prep_person_preserves_head_and_exif`).

### 5. Pick the best saved photo FOR THE GARMENT being tried on (v0.13.0)
**What the user asked for:** the photo used to generate a try-on should be chosen
by what's going to be tried on — if the garment is a swimsuit, use a saved photo
where the person is already in a swimsuit/minimal outfit; if it's a dress, use a
dress photo; and vice versa. **Not** a geometric heuristic.

- **How it works:** `app/photopick.py` sends the garment image + every saved
  photo to the Ollama vision LLM (`qwen2.5vl:3b`, same model as ai-fill) in ONE
  multi-image call and asks it to score each photo as the try-on base, weighted
  on outfit type/coverage match. The best-scoring photo is auto-selected in the
  Saved-photo dropdown and is what generates the render.
- **Fallback:** if the vision model is down/unparseable, `imageqa.suitability()`
  (pure-PIL person QA nudged by garment category) is used so it never blocks.
  Vision-skipped photos are filled in with the heuristic so every photo stays
  ranked.
- Endpoint: `GET /api/photos/best-for-garment/{garment_id}` →
  `{garment_id, garment_name, method: ai|heuristic, best_id, best, ranked:[…]}`
  (each ranked entry: photo fields + score/grade/reason/method).
- Frontend: picking a garment in the look (or the recommendation) calls the
  endpoint; the best photo is auto-selected and a hint shows: "✨ Using the best
  saved photo to try on <garment> — Great (91/100) — swimsuit base matches".
  One manual pick in the dropdown stops auto-overriding.
- **Bug fixed along the way:** `wardrobe_routes.py` used `Form` without importing
  it (broke `app.main` import entirely — would have stopped the app on next
  deploy).
- **PWA cache bump v2 → v3** (sw.js): static assets are SW cache-first, so
  without a bump clients kept serving the stale v0.12-era tryon.js and never saw
  the auto-pick. **Bump `CACHE` in `services/webapp/app/static/sw.js` on every
  JS/CSS release** or users won't get the new code (phones especially).
- Files: `app/photopick.py` (new), `app/routes/photos_routes.py` (replaced the
  category-only `/api/photos/suitability`), `static/js/tryon.js` +
  `templates/tryon.html` (auto-pick hint), `static/sw.js` (cache v3).

### 6. Garment orientation — "look, then rotate" (v0.14.0, latest)
**The fix the user pushed for** (after "rotate-then-read-text" and a deterministic
EXIF+portrait pipeline both left folded flat-lay photos sideways / inconsistent).

- **How it works:** `aifill.ai_upright_rotation()` asks the Ollama vision model
  (`qwen2.5vl:3b`) one question per photo: *"which edge is the garment's top on?
  (top/bottom/left/right)"* — `_top_edge()`, 3-vote majority with early-exit. The
  photo is then rotated so that edge is the **TOP** edge. Mapping: top→0,
  bottom→180, left→90 CW, right→270 CW. Returns `None` when unsure → caller falls
  back to deterministic EXIF + portrait.
- **Why it works where the others failed:** on folded flat-lays "is it upright?"
  gets YES at every rotation (a folded garment has no up/down), and the tag-reader
  only worked when a tag was readable. The edge question is stable (3/3 agreement
  on all 20 photos) and needs no readable tag.
- **Wiring:** `media.save_garment_image(..., ai_orient=True)` runs it on **every**
  upload (no exceptions). `normalize_orientation(data, rotate, ai_decided)` — when
  `ai_decided=True` the AI's answer is trusted even when it's 0 (already upright),
  so the landscape→portrait guess is skipped.
- **Backfill:** `scripts/backfill_orientation.py` (run inside the webapp container)
  re-processed all stored photos. Result: 17/20 were already upright; **#119
  (olive joggers), #122, #124** (top on left) were rotated upright. All 20 now read
  "top" — consistent.
- **GOTCHAS learned:** (a) hammering the small vision model with rapid back-to-back
  calls makes it return `"????"` garbage — pace calls with ~0.4s sleeps; `ollama
  stop qwen2.5vl:3b` reloads it. (b) The user said "rotate so it's horizontal" but
  17/20 photos were already upright, so the 3 sideways ones were rotated to match
  (upright) rather than flipping 17 good photos sideways. If the user truly wants
  everything horizontal (top on left), it's a one-line flip in `_EDGE_TO_CW`.
- Backup of the pre-fix images: `~/wardrobe-backup-20260822-162845.tgz` on 202.

  the person's pose/mask, CatVTON can stretch it. Under investigation: could try
  adjusting cloth_type (dress → overall), or the mask; not yet solved.

  full-body, well-lit, high-res, upright photos with neutral/simple clothing and
  arms slightly away from the body; avoid extreme crops, wide/long poses, and
  landscape-stored (EXIF-rotated) shots (now auto-corrected, but still best to
  provide proper portrait files). Not yet surfaced in the UI (could be a help

## Architecture recap (files)
- `services/webapp/app/aifill.py` — `_top_edge()` / `ai_upright_rotation()`
  (orientation "look, then rotate", §6) + the earlier tag-read `ai_orientation`
  + `ai_fill_garment` (metadata tag-read).
- `services/webapp/app/media.py` — `normalize_orientation(data, rotate, ai_decided)`
  + `save_garment_image` (auto-orients every upload; HEIC→JPEG; phash/color_sig).
- `services/webapp/scripts/backfill_orientation.py` — re-orients existing photos.
- `services/webapp/app/tryon.py` — CatVTON client + `_prep_person` (head fix).
- `services/webapp/app/svd.py` + `workflows/svd.json` — SVD motion clips.
- `services/webapp/app/clips.py` — ClipStore (async job tracking).
- `services/webapp/app/photopick.py` — pick the best saved photo for a SPECIFIC
  garment by outfit match (Ollama vision; `imageqa.suitability` fallback).
- `services/webapp/app/imageqa.py` — person/garment QA + `suitability()` scorer
  (used as the no-vision fallback).
- `services/webapp/app/routes/photos_routes.py` — incl.
  `GET /api/photos/best-for-garment/{id}`.
- `services/webapp/app/routes/tryon_routes.py` — tryon/outfit + clip endpoints,
  auto-save, uploads serving (png/webp).
- `services/webapp/app/routes/outfits_routes.py` + `outfits.py` — outfit CRUD,
  person mapping fields.
- `services/webapp/app/db.py` — schema/migrations: `clips` table, `outfits`
  `motion_url`/`person_photo_id`/`person_url`, `garments` `owned`/`created_at`.
- `services/webapp/app/static/js/tryon.js`, `outfits.js` + templates — UI.
- `services/webapp/app/version.py` — `__version__ = "0.13.0"` (single source).
- `services/comfyui/Dockerfile` — CatVTON node baked in; SVD model is a runtime
  symlink (see note above).
